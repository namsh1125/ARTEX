# 취약점의 다중 트래픽 증거

취약점 상세의 「연결된 트래픽」에서 페이지 간 다중 선택, 용도·설명 편집, 정렬 및 연결 해제를 지원합니다. 트래픽 페이지에서도 여러 기록을 선택하여 기존 취약점 하나에 연결할 수 있습니다. 다른 작업에서 상속한 증거는 읽기 전용이며 수정하려면 원본 작업으로 이동해야 합니다.

시스템 설정의 「에이전트 트래픽 자동 연결」은 기본적으로 꺼져 있습니다. `/api/settings`의 `agent_traffic_binding`으로 조회·변경합니다. 활성화하면 요청·응답 확인, 도구 호출 및 프롬프트로 인한 토큰 사용량이 증가하며 다음 에이전트 실행부터 적용됩니다. 끄면 자동 연결 매개변수와 추가 연결 도구를 숨기고 안내를 주입하지 않으며 이미 실행 중인 세션의 새 자동 연결도 거부합니다. 수동 연결, 트래픽 캡처, 저장된 증거 읽기 및 내보내기에는 영향을 주지 않습니다.

활성화 시 기본 흐름은 「취약점 저장 → 보고서 에이전트 자동 실행 → 트래픽 확인·연결 → 최신 증거 버전으로 보고서 작성」입니다. 보고자는 `evidence`에 검증 명령, 주요 출력, 이미 확보한 실제 트래픽 ID와 용도를 남깁니다. 보고서 에이전트는 취약점 상세 및 실행 기록과 함께 `traffic_search` / `traffic_get`으로 확인한 뒤 `bind_finding_traffic`을 호출하고 최신 `version`을 읽어 보고서를 저장합니다. 끄면 보고서 에이전트에 원본 트래픽 검색·읽기 도구를 추가 제공하지 않으며 자동 연결도 하지 않습니다. 수동으로 연결한 스냅샷은 읽고 보고서에 사용할 수 있습니다.

기존 호출과의 호환성을 위해 `report_finding`의 `traffic_refs` / `evidence_hint_id`로 즉시 명시적 연결할 수 있습니다. 연결은 선택 사항입니다. TCP 등 HTTP가 아닌 취약점, 미수집 또는 정확한 기록을 찾지 못한 경우에도 참조 없이 보고할 수 있습니다. 명령 출력·로그 등 검증 가능한 다른 증거를 보존하고 미연결 사유를 설명하는 것이 좋지만 필수 필드를 추가하지 않습니다. 제출한 ID는 모두 유효하고 본문이 완전해야 합니다. 하나라도 실패하면 이번 연결을 롤백하며 보고와 함께 연결한 경우 보고 전체를 롤백합니다. 같은 스냅샷을 다시 추가해도 중복 연결하거나 설명을 덮어쓰지 않습니다.

## 에이전트 ID와 보고서 버전

`report_finding`에 다음 선택 매개변수를 추가합니다. 배열 순서가 초기 증거 순서입니다.

```json
{
  "traffic_refs": [
    {"traffic_id": "실제 트래픽 ID", "role": "baseline", "note": "정상 계정 요청"},
    {"traffic_id": "다른 실제 트래픽 ID", "role": "proof", "note": "재현 요청"}
  ]
}
```

용도는 `baseline`(정상 대조군), `proof`(취약점 입증), `verification`(추가 검증), `supporting`(보조 증거, 기본값)입니다. 먼저 `traffic_search` / `traffic_get`으로 실제 기록을 확인합니다. 도메인과 시간은 후보 필터에만 사용하며 작업 소속을 추정하지 않습니다.

프롬프트는 [CyberStrikeAI의 취약점 보고 도구 안내](https://github.com/RuoJi6/CyberStrikeAI/blob/54d56774b8bd285817d16d48b70a4a5e6e0963f7/internal/app/vulnerability_tools.go)를 참고하되 선택적 연결 원칙을 적용합니다. 패킷 부재 사유를 필수로 검증하지 않습니다. ID를 추측하거나 패킷을 채우기 위해 탐색을 반복해서는 안 됩니다.

첫 반환 줄은 기존처럼 `finding recorded: <탐색 노드 ID>`입니다. 이어지는 JSON에는 독립 취약점 기록의 `finding_id`, 탐색 노드의 `finding_node_id` 및 연결 요약을 제공합니다.

- `get_finding_traffic(finding_id)`는 **독립 취약점 기록 ID**를 사용하며 순서 있는 목록과 `version`을 반환합니다. `binding_id`, `side=request|response`, `offset`, `length`로 본문을 나누어 읽을 수 있으며 한 번에 최대 8192바이트입니다.
- `update_finding_report`의 `finding_id`는 계속 **탐색 노드 ID**입니다. `evidence_version`에는 실제로 읽은 버전을 전달합니다. 생성 도중 증거가 바뀌면 이전 버전의 쓰기를 거부하므로 다시 읽고 생성해야 합니다.
- 이전 방식처럼 버전을 전달하지 않은 보고서는 기존 트래픽 증거를 반영했다고 간주하지 않습니다. 연결, 설명, 용도 또는 순서가 바뀌면 기존 보고서에 갱신 필요 표시를 합니다.

자동 연결이 켜져 있으면 `add_hint` / `add_task_hint`는 단일 힌트 또는 `hints` 배열의 각 요소에 `traffic_refs`를 저장할 수 있습니다. planner가 대신 보고할 때 `evidence_hint_id`로 현재 작업의 힌트를 명시적으로 선택할 수 있지만 상속한 힌트는 참조할 수 없습니다. 시스템은 도메인, 시간 또는 조회 기록으로 연결을 추측하지 않습니다. 제출 실패 시 일부 취약점을 만들거나 보고서를 미리 실행하지 않습니다.

기존 취약점의 누락 연결은 `bind_finding_traffic(finding_id, traffic_refs)`로 보완하며 다시 등록하지 않습니다. `list_findings` / `list_task_findings` / `node_detail` / `get_task_node_detail`은 명시적인 `finding_id`와 `finding_node_id`를 반환합니다. 기존 `id`는 탐색 노드 의미를 유지합니다.

시작 시 이전 도구 스키마에 선택 속성만 추가하고 기본 트래픽 도구 연결을 보고서 에이전트로 확장합니다. 추가 연결 도구도 기본적으로 보고서 에이전트에 제공합니다. 사용자 지정 연결 목록, 프롬프트, 설명 및 활성 상태는 유지합니다. 최종 도구 구성 후 안내를 통합 주입합니다. 보고 역할은 기존 증거를 넘기고 보고서 에이전트는 확인·연결·작성을 맡습니다. 플랫폼 대화에 작업 컨텍스트가 없으면 직접 보고하지 말고 구조화된 힌트로 작업 에이전트에 전달합니다. 완료 판단 전에 기존 증거를 전달하되 패킷이 없다고 강제로 기다리지 않습니다. 실패한 `report_finding`은 보고서 에이전트를 실행하지 않습니다.

## API

기본 경로는 `/api/exploration/findings/{finding_id}/traffic`이며 독립 취약점 ID를 사용합니다. 기존 인증을 사용하고 `context_task`로 작업 접근 권한 및 상속 읽기 전용 여부를 확인합니다.

| 메서드 / 상대 경로 | 요청 / 반환 |
| --- | --- |
| `GET` | 순서 있는 요약, 증거 버전, 보고서가 사용한 버전 |
| `POST` | `{"traffic_refs":[...]}` 전체 묶음 추가 |
| `PATCH /{binding_id}` | `{"version":1,"role":"proof","note":"설명"}` |
| `DELETE /{binding_id}` | `{"version":1}` |
| `PUT /order` | `{"version":1,"binding_ids":["2","1"]}`. 전체 목록 필수 |
| `GET /{binding_id}` | 스냅샷 메타데이터 및 제한된 본문 미리보기 |
| `GET /{binding_id}/body` | `side`, `offset`, `length`. `download=1`이면 전체 원본 바이트 다운로드 |

버전·순서 집합 충돌 또는 보관 중 쓰기는 `409`, 상속 항목 쓰기는 `403`, 존재하지 않거나 해당 취약점 소속이 아닌 연결은 `404`를 반환합니다. 트래픽·첨부 파일 읽기나 검증 실패도 명확한 오류로 반환합니다.

## 저장 및 마이그레이션

시작 시 PostgreSQL에 `traffic_evidence_snapshots`, `finding_traffic_bindings`, `findings.evidence_version` / `report_evidence_version`(기본 0)을 멱등하게 추가합니다. 과거 텍스트를 추측하여 자동 연결하지 않습니다.

스냅샷에는 원본 트래픽 ID, 수집 시각, URL, 메서드, 상태, 요청·응답 헤더, 본문 길이 및 SHA-256을 저장합니다. 본문은 해시별로 `<data>/evidence/blobs/<앞 두 자리>/<hash>.bin`에 저장하여 정리 가능한 `data/traffic`과 분리합니다. 여러 취약점이 스냅샷과 본문을 공유할 수 있습니다. 스냅샷 내용 수정 API는 없으며 무결성이 일치하지 않으면 읽기와 내보내기를 실패 처리합니다.

원본 트래픽 쓰기 잠금 아래에서 큰 본문 blob과 이전 디렉터리 기록을 포함한 전체 본문을 읽습니다. 파일을 먼저 영구 저장·검증하고 단일 PostgreSQL 트랜잭션으로 탐색 노드, 의도 관계, 취약점, 스냅샷 및 연결을 기록합니다. 커밋 후에만 planner에 알립니다. 실패 시 참조 없는 파일은 남을 수 있지만 일부 업무 기록은 만들지 않습니다.

PostgreSQL advisory lock `7337741004`로 증거 파일과 SQL 참조를 조정합니다. 작업 행 잠금으로 보관 대기열 진입 후 증거 수정을 막습니다. 복원은 본문 설치부터 메타데이터 커밋까지 증거 잠금을 유지합니다. 취약점을 삭제하면 연결도 연쇄 삭제합니다.

정리기는 매시간 실행하며 참조가 없고 진행 중인 작업에서 사용하지 않는 내용을 최소 24시간 뒤 회수합니다. 일반 트래픽 정리는 증거 디렉터리를 건드리지 않습니다. 활성 데이터를 백업할 때 PostgreSQL과 `data/evidence`를 함께 백업합니다.

## 내보내기 및 보관

Markdown에는 순서 있는 증거 목록과 버전, JSON에는 메타데이터, CSV에는 개수와 연결 ID를 포함합니다. `md-zip`은 취약점 Markdown과 다음 파일을 제공합니다.

```text
evidence/<finding_id>/<binding_id>/
  manifest.json
  request.http
  response.http
  request.bin
  response.bin
```

Markdown은 상대 링크로 패킷을 참조합니다. 다운로드 전 첨부 복사, 해시 검증, 압축, 디스크 동기화 및 모든 ZIP 항목의 CRC 읽기 검증을 완료합니다. 누락·손상 시 전체 다운로드가 실패하며 첨부는 원본 바이너리 바이트를 유지합니다.

보관 v3는 원본 트래픽이나 도메인에 의존하지 않고 취약점 연결 관계로 스냅샷과 본문을 수집합니다. 패키지를 검증한 후 활성 데이터를 정리하고 공유 증거는 유지합니다. 복원은 본문 검증·설치 후 트랜잭션으로 메타데이터와 연결을 복원하며 실패 시 재시도할 수 있습니다. v1/v2도 계속 복원 가능하며 없는 새 필드는 명시적으로 0으로 채웁니다.

## 검증 및 한계

테스트 패키지마다 새 독립 PostgreSQL 데이터베이스를 만들고 `ARTEX_PG_DSN`으로 지정하여 잔여 작업·모델 픽스처의 백그라운드 실행을 방지합니다. 관련 패키지 전체 테스트를 실행하고 설정 누락으로 건너뛴 항목이 없는지 확인합니다.

```sh
# 패키지마다 독립 테스트 DB를 ARTEX_PG_DSN으로 지정합니다. 명시한 설정 연결 실패는 오류여야 합니다.
go test ./<package> -count=1
go test -race -p 1 ./evidence ./db ./agent ./server -run 'TestEvidence|TestFindingTraffic|TestFindingEvidence|TestReportFindingAtomicContract|TestTaskArchive'
```

프런트엔드는 `npx tsc --noEmit`, 변경 파일의 Biome 검사, Webpack 빌드 및 `NEXT_EXPORT=1` 정적 내보내기를 검증합니다. 실행 중인 개발 서비스의 캐시를 덮어쓰지 않도록 독립 캐시 디렉터리를 사용합니다.

로컬 종단 간 검증은 독립 포트, 통제된 HTTP 및 도메인 HTTPS 대상, 임시 데이터 디렉터리를 사용합니다. 두 연결 진입점, 페이지 간 선택, 순서·설명 변경, 오류 안내, 상속 읽기 전용, 다운로드와 함께 원본 트래픽 삭제 후 내보내기·보관·활성 본문 회수·복원·해시 검증을 확인합니다.

초기 버전은 전역 증거 조정 잠금을 사용하므로 대량 연결·내보내기 또는 느린 첨부 다운로드 중 다른 증거 작업이 기다릴 수 있습니다. 기록이나 전체 본문이 없으면 증거를 만들어 보완할 수 없습니다. 캡처 스위치나 HTTPS로 IP에 직접 접근할 때의 인증서 문제는 이 기능의 범위가 아닙니다.
