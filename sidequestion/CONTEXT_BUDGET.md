# 별도 질문의 긴 대화 및 컨텍스트 예산

2026-09-11에 수정한 내용입니다. 이전 구현은 요청 JSON의 문자 수를 토큰 수로 간주하고 주 작업의 32K 출력 예약량을 상속하여 HTML, JS 및 도구 결과가 많으면 정상 질문을 너무 일찍 거부했습니다.

## 오픈 소스 구현 비교

- [Grok CLI 별도 질문 컨텍스트](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/agent/agent.ts#L739): 최근 사용자·도우미 텍스트에서 총 약 2000자, 항목당 최대 400자를 추출합니다. 해당 경로에서는 연속 질의응답 기록을 유지하지 않습니다.
- [Grok CLI 독립 요청](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/utils/side-question.ts): 독립 취소 신호, 모델이 지원할 경우 출력 최대 2048토큰, 도구 미제공.
- [Grok CLI 주 세션 압축](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/agent/compaction.ts): 토큰 추정, 최근 내용 유지, 기존 요약에 새 내용 반영 및 대화 경계를 넘는 절단 처리.
- [OpenCode 세션 압축](https://github.com/anomalyco/opencode/blob/b3f1a96c6dd7adeb28b36dd11add1998fc84d67b/packages/core/src/session/compaction.ts): 전체 요청 추정, 출력·버퍼 예약, 최근 내용과 누적 요약, 도구 없는 요약 요청. 기본 최근 예산은 8000, 요약 출력 한도는 4096토큰.
- [OpenCode 초과 복구](https://github.com/anomalyco/opencode/blob/b3f1a96c6dd7adeb28b36dd11add1998fc84d67b/packages/core/src/session/runner/llm.ts): 도우미 출력을 시작하기 전에만 복구하며 복구한 호출은 같은 복구 경로로 다시 들어가지 않습니다.

ARTEX는 독립 출력 예산, 최근 내용과 누적 요약, 제한된 복구를 참고했습니다. norma v0.3.6의 구조화 메시지와 도구 짝을 유지하며 Grok의 텍스트 추출을 그대로 사용하지 않습니다. OpenCode의 주 세션 압축 이벤트를 ARTEX 주 transcript에 기록하지 않습니다.

## 요청 예산 및 실행

- 메시지는 norma의 콘텐츠 블록별 UTF-8 바이트 추정과 4/3 여유율을 사용합니다. 시스템 프롬프트, 도구 스키마 및 메시지 포장 비용도 추가합니다. 모델의 정확한 토큰 수는 아닙니다.
- 별도 질문 출력은 기본 최대 8192토큰이며 주 설정의 출력 한도를 넘지 않습니다. 서비스 환경 변수 `ARTEX_BTW_MAX_OUTPUT_TOKENS`로 256–32768 범위에서 지정할 수 있습니다. 제품 기본 모델이나 주 작업 매개변수는 변경하지 않습니다.
- 입력 예산은 컨텍스트 창에서 출력 한도와 안전 여유를 뺀 값입니다. 창 크기를 모르면 플랫폼 기본 200K를 사용합니다. 안전 여유는 창의 5%이며 최소 128, 최대 8192토큰입니다.
- 성공한 질의응답을 증가 순번으로 한 번에 최대 20개 불러옵니다. 원문은 최대 20개이며 입력 예산의 1/4 또는 16K 중 작은 값으로 제한합니다.
- 초과한 질의응답은 출처와 컨텍스트 시각을 포함한 누적 요약에 반영합니다. 이전 도우미 답변은 새 도구 증거와 동등하지 않으며 충돌 시 최신 주 스냅샷을 우선합니다.
- 주 컨텍스트가 여전히 길면 사본의 이전 메시지만 요약하고 최근 최대 8K토큰을 유지합니다. 도구 호출과 결과를 분리하지 않으며 너무 큰 한 묶음은 통째로 요약합니다.
- 요약 입력은 실제 남은 창 크기에 맞춰 UTF-8 안전 경계로 나누고 출력은 최대 2048토큰입니다. 빈 요약, 잘린 요약, 도구 호출 또는 예산 초과 결과는 캐시하지 않습니다. 별도 질문 하나당 최대 12회 요약하며 동일한 120초 제한을 적용합니다. 한도 도달 시 명확하게 실패하고 무한 반복하지 않습니다.
- 모델의 첫 컨텍스트 초과 오류가 텍스트·도구 호출 출력 전에 발생하면 더 줄여서 한 번만 재시도합니다. 추정 크기가 줄지 않으면 즉시 복구를 중단합니다. 다른 오류나 부분 스트리밍 출력에는 이 복구를 적용하지 않습니다.
- 요약, 실패한 시도 및 취소 시 받은 사용량을 같은 요청에 누적합니다. Provider가 사용량을 반환하지 않으면 0으로만 기록하며 추정치를 실제 사용량으로 표시하지 않습니다.

## 저장 및 UI

`side_question_sessions.memory`에는 이전 질의응답 요약, 포함한 ordinal 및 스냅샷 식별자별 주 컨텍스트 요약 캐시를 저장합니다. `side_question_requests.context_info`에는 준비 단계, 실제 재생 개수, 요약 사용 여부 및 예산 추정치를 저장합니다.

원래 요청이 실행 중이고 정리 버전이 일치할 때만 요약을 저장합니다. 기록 비우기는 캐시도 지우며 늦은 쓰기로 복원되지 않습니다. 새 스냅샷은 이전 스냅샷 요약을 재사용하지 않습니다. 요약 필드는 v3 보관에 포함합니다. 이전 v3에 필드가 없으면 빈 객체로 채우며 v1/v2도 호환합니다.

POST는 요청을 접수한 뒤 즉시 반환합니다. 준비·압축은 백그라운드에서 실행하며 진입 잠금이나 DB 트랜잭션을 유지하지 않습니다. SSE와 기록에는 준비, 질의응답 정리, 사본 압축 및 답변 단계를 표시합니다. 압축 실패는 요청의 실패 상태로 저장합니다. 프런트엔드는 오류를 유지하고 실패한 질문을 초안으로 복원하며 입력창을 가리는 토스트를 사용하지 않습니다. 기록 폴링이 제출 오류를 지우지 않도록 했습니다.
